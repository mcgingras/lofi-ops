# Perks and killstreaks (area: perks-streaks)

BO1-faithful perks (three tiers, Pro versions) and killstreaks (pick three, Hardline-aware), plus MW2's Tactical Nuke, server-authoritative, with client visuals, sounds, HUD and a radar minimap. Bots use streaks on their own, scaled by their `streakUse` skill, so a bot-backfilled lobby plays the same as a full one.

**Sprint stamina (everyone).** BO1 sprint runs out: 5 s (Marathon 10 s, Pro unlimited), regains 1 s/s, needs 1.2 s before sprinting again. Enforced through the new core `canSprint` modifier, so client prediction follows (`me.params.canSprint`). Tune in `PERK_TUNING`.

**Pro.** A perk is Pro when `profile.challengeProgress[<perk>_pro] >= goal` (or the profile's `unlocks` contains `<perk>_pro`). The perks feature counts its own `perks.*` metrics and writes `challengeProgress` directly (humans only), emits `perks.progress`, and pushes a "X Pro unlocked" notice. Bots: set `player.ext.perks.allPro = true` to give a bot every Pro (e.g. for hardened/veteran). RPC `perks.pro` returns `{ pro, progress }` for create-a-class.

## Tactical Nuke (MW2)

Reference: the Call of Duty Wiki "Tactical Nuke" page (MW2 section) and MW2 footage. 25 kills in a row (24 with Hardline), unlocked at level 10 in MW2 (25 here). Once called, a ten-second countdown shows on every screen with a siren; the bomb lands off the map; the battlefield goes white, time slows, every killstreak explodes and every player dies, nearest to the blast first; the match is a win for the caller's side whatever the score, and scores freeze from the call. It can't be shot down or stopped.

- **Kill counting (option in the defs).** `KillstreakDef.countsStreakKills` (default false = the BO1 rule). The nuke sets it to **true**: MW2 counted every kill toward the nuke, and 25 gun kills in a row against bots is a very long ask; the BO1 streaks still ignore streak kills. Set it to false on the nuke's def for the strict rule. The ladder push carries `countAll` so the HUD fills the nuke's (compact, grouped by five) pips with every kill.
- **Call-in.** STREAK with the nuke selected (`targeting: 'none'`) calls it at once (`streaks/nuke.ts`): the caller's weapon is down for `NUKE.laptopSec` (1.5 s) while their first-person laptop opens and they press the arming key; then the 10 s countdown. One `ks_nuke` entity sits at the blast point (`blastPoint`: map centre + half extent + 110 m in a random direction) with `s = { a: countdown start, d: detonation, n/f: nearest/farthest distance of the map from the blast, o: owner id }` (no `owner` field, so core doesn't remove it if the caller leaves; it is not in the active's entity list, so it stays through the results until the next match start). A second nuke while one is inbound: `nuke_active`.
- **Match end lock.** The call sets core's `room.endLock = 'nuke'`: team/player score changes are ignored and only `endMatch('nuke')` can end the match, so no score, time or round limit (S&D) beats the bomb.
- **Detonation** (`d`): every other killstreak is finished (blast effects, no announcements), nobody respawns (`respawnAt = null`), movement slows (`speedMultiplier` `nukeTimeScale`, down to x0.35 for 4.5 s; no sprint). From `d + 2 s` the shockwave kills each living player when it reaches them (`shockAt(dist)`: nearest at +2 s, farthest at +4 s), `room.kill(p, caller, { weapon: 'nuke', means: 'nuke' })` (kills credited to the caller; the caller and team mates die too, uncredited). At `d + 5.5 s`: `room.endMatch('nuke', nukeResults(...))` = the mode's own results with `winnerTeam` = the caller's team (FFA: winners = the caller, placed first). It still goes off if the caller dies or leaves (`Active.keepOnLeave`).
- **No killcams.** `means: 'nuke'` is in `NO_DEATHCAM_MEANS` and the modes feature skips the final killcam when `results.reason === 'nuke'`.
- **XP, challenges.** Calling emits `progression.xp` ("TACTICAL NUKE", 2,500 XP) and every streak call emits `progression.metric` `streak_called {killstreak}`; `ks_nuke_called` ("End Game", 1/5/10 calls) counts it. `ks_nuke_earned` / `ks_nuke_kills` come from the generic per-streak challenges. CoD Points, XP and challenges run through the normal match end.
- **Bots** earn it like players and call it through the same API (`callKillstreak(room, bot, 'nuke')`, automatic use calls the highest streak first). Bot loadouts can pick it (rarely for weak bots).
- **Client** (`nuke.ts`, maths in `nuke-logic.ts`): the caller's laptop in first person (rugged olive case, red warning screen, gloved hand on the key, drawn over the world like the radio); a countdown for everyone ("TACTICAL NUKE INCOMING", the number, a line per side: mine / friendly (with the caller's name) / enemy, then "IMPACT IN 3..1") plus the generic "Friendly / Enemy Tactical Nuke inbound" announcement; at detonation the screen washes to white through the post pass (`renderer.white`, before the dither), eases down to a washed-out view of a low-poly mushroom cloud (cap, crown, glowing under-ring, stem, condensation ring, dust base, smoke texture from a greyed photo; white-hot to fire to ash) and an expanding dust wall (the shockwave), slow mouse look and camera shake; white again when the shockwave reaches you (or kills you), held until the results, whose reason reads "TACTICAL NUKE". A nuke death shows no "killed by / respawn" card.
- **Sound** (reused ids, nothing new while the sound rework is in flight): the bomb beep (`modes.beep`) once per countdown second, `ks_bigboom` slightly lowered (rate 0.9, low-pass 900 Hz) at detonation and again (rate 0.94) when the shockwave reaches you. Big pitch-downs were dropped after the sound rework: they read as cartoonish.

**Controls.** `4` (STREAK button): call the selected streak. The Care Package and the Valkyrie drop (`targeting: 'marker'`) raise the marker canister and FIRE throws it (next section); the Valkyrie launcher comes up with STREAK and FIRE launches (below). The Sentry Gun and SAM Turret come up in your hands and FIRE or USE places them (below). Napalm, Mortar Team, Rolling Thunder and the Attack Helicopter (`targeting: 'map'`) open the **tactical map** (below). `5` cycles the selection (RPC `killstreaks.select`). While holding the marker or the radio, designating or driving, core firing is refused (the feature holds `swapEnd`); holding the radio or driving, the body's speed is 0.

## Sentry Gun and SAM Turret (BO1 carry-to-place)

Sources: the T5 script dump (plutoniummod/t5-scripts) `maps/mp/_turret_killstreak.gsc` (carry, placement, lifespan, health, hacking, stuns) and `maps/mp/_mgturret.gsc` (burst fire, difficulty "fu"); the engine's turret code in the KisakBlack T5 decompile (`src/game/turret.cpp`, `src/bgame/bg_perks.cpp`, `bg_weapons_load_obj.cpp`); the Call of Duty Wiki "Sentry Gun" (Black Ops and MW2 sections), "Ghost (perk)" and "Hacker (perk)" pages. BO1's turret weapon file `auto_gun_turret_mp` (arcs, turn speeds, damage, range) is in neither the script dump nor any mod we could find; MW2's `sentry_minigun_mp` (IW4 weapon file) stands in where noted. What BO1 did:
- **Duration:** `level.auto_turret_timeout = 90.0` s, counted (in 1 s steps) only while it stands on the ground (`watchTurretLifespan`: `if (!self.carried) curr_time += 1`). The SAM (`tow`) uses the same timeout.
- **Arming and acquisition:** after it is put down, `turretInitDelay` 1.0 s before `burst_fire_unmanned` starts. Turret difficulty "fu": `convergenceTime` 0.4 s, `accuracy` 0.38, `playerSpread` 0.5, `suppressionTime` 3. The engine keeps a sentry locked on a target for `turret_SentryTargetTime` 1000 ms before re-checking sight. Turn speed: not found for BO1 (MW2: `maxHorTurnSpeed` 60 deg/s, `yawConvergenceTime` 1 s).
- **Fire:** `do_shoot` fires one round per 0.112 s (~535 rpm) in bursts of 0.5 + rand(4) s with pauses of 0.2 + rand(0.5) s, and plays `mpl_turret_alert` when it starts firing. Damage per round: not found for BO1 (MW2: 20 flat).
- **Range and arc:** not found for BO1. The engine reads `leftArc` / `rightArc` / `topArc` / `bottomArc` and `maxRange` from the weapon file, and the wiki describes a cone in front of where it was placed (flanking it works); MW2's file: 55 degrees each side, 45 up, 20 down, 1800 units (46 m). Idle, it scans (engine `Turret_ScanForEnemies`).
- **Health:** 1000 with bullets doing 30% (`bulletDamageReduction` 0.3, plus Hardened's armor-piercing bonus), explosives full, any melee kills it (`MOD_MELEE` sets the damage to its health). Flashbangs and concussions stun it for 5 s (`stunDuration`); the Jammer (scrambler) stuns it while in range. Smoke and Nova Gas don't blind it (wiki).
- **Carry and move:** calling it puts it in your hands (`startCarryTurret`, `CarryTurret` 40 units in front, weapon disabled); `canPlayerPlaceTurret` every 50 ms with yellow / red models for good / bad spots (trigger_hurt, minefields and `no_turret_placement` volumes are bad); FIRE places it; the killstreak button before the first placement puts it away and gives the streak back, as do death and last stand. The owner can pick a placed one up again with USE (an owner-claimed `trigger_radius_use`, on the ground, not throwing, meleeing or firing); dying while carrying a picked-up one places it if the spot is good, else destroys it.
- **Hacker:** Hacker Pro (`specialty_disarmexplosive`) holds USE on it (`hackerResult`; `perk_disarmExplosiveTime` is 2.0 s by the engine default, the wiki says 3 s): it changes team and owner, is stunned 2.5 s and keeps its lifespan; the hacker can't pick it up (only the original owner hacking it back gets the pickup trigger back). BO1 has no EMP: tacticals and the Jammer are the stuns.
- **Ghost:** Ghost Pro gives `specialty_nottargetedbyai`: the engine skips that player when the sentry picks a target (`turret_findBestTarget`), but rounds at others still hit them. (That Ghost Pro's row carries that specialty is inferred from the engine check and the wiki; BO1's statsTable wasn't available.) MW2's equivalent was Cold-Blooded; we have no Cold-Blooded.

Ours (`shared/defs/sentry.ts`, `shared/defs/turret-place.ts`, server `streaks/turrets.ts`, `streaks/carry.ts`, `streaks/turret-damage.ts`, client `turret.ts` and the renderers):
- **Why these numbers.** The complaint was that it was too strong and lasted too long, so where BO1 is unknown we took the less oppressive side. Duration **60 s** (BO1 90 s, which is what felt too long; 60 s matches our other timed streaks), counted only on the ground. **Arc** 55 degrees either side of the way it was placed facing (MW2's 55). **Turn rate** 60 deg/s (MW2's `maxHorTurnSpeed`): someone circling it up close outruns it. **Acquisition** 0.6 s between first seeing you and the first round (BO1's alert plus convergence; "fu" converges in 0.4 s), and a target out of sight for 0.3 s is dropped, so each new peek pays it again (BO1 held a lock for 1 s). **Arming** 1 s after it goes down (BO1). **Fire** one round per 0.112 s in BO1's bursts and pauses. **Damage** 20 per round up to 8 m, down to 12 at 30 m (MW2: 20 flat). **Accuracy** 85% of rounds hit up to 6 m, falling to 20% at its 35 m range. **Health** 500, bullets 0.8x (about 16 rifle rounds, so shooting it from the side or behind is a real counter; BO1's 1000 at 0.3x took ~80), explosives 2x (two close frags), the knife kills it.
- **Targeting** (server, every tick once armed and not stunned): the nearest enemy in range and arc it can see from its muzzle by the bots' sight rules (`bots/sight.ts` `botCanSee`: collision's sight mask plus drawn cover; the chest, else the eye over cover), skipping Ghost Pro (`streakTargetable`). It turns its head at the turn rate, clamped to the arc, and fires only when aligned (within 3.4 degrees), past the acquisition delay, while it sees the target this tick and a round would reach it (`botCanHit`). Rounds go through `fireBullet` (hit chance by distance; a miss flies past; the world stops them). With no target it sweeps its arc at 34 deg/s.
- **Cues.** The tripod stays the way it was placed (`s.b`) while the head turns. A red lamp blinks while it tracks someone (`s.t` = their id) and burns steady once it may fire (`s.a`), and it chirps (`weapons.beep`) when it picks up a target, standing in for BO1's alert. The player it tracks also sees a red laser from its muzzle to them (pulsing while it acquires, steady once it may fire) and a red "SENTRY" marker on it. Stunned (`s.st`): sparks, no lamp. (BO1's cue was the alert sound; the lamp and laser are ours, for readability.)
- **Carrying** (`streaks/carry.ts`, `ks.carry`, pushed as `killstreaks.state.carry {id, moved}`): STREAK (4 / D-pad up) with either turret selected brings it up: weapon down (the server holds `swapEnd`), x0.75 speed, no sprint, USE claimed. The rule is `turretPlacement(world, map, feet, yaw)`: 1.5 m in front of your feet (BO1's 40 units is 1 m; further here so the preview doesn't fill the view), on a floor from 1 m below to 0.6 m above your feet, nothing between your chest and it, flat (the floor under its footprint's edges within 0.2 m), room for a 0.38 m x 1.1 m turret, inside the map (1 m in), and no higher than the Care Package's roof limit (highest spawn + 4.5 m); reasons `bounds`, `nofloor`, `blocked`, `steep`, `solid`, `roof`. The client draws a ghost of the turret there every frame from its predicted feet and quantised aim (green / red, a spinning ring, the Sentry's arc on the floor), with "CAN'T PLACE: BLOCKED" (etc.) and "[LMB] PLACE SENTRY GUN  [4] CANCEL" (`promptKey`: "[RT] ... [↑]" on a pad). Others see the turret in front of the carrier, tinted green / red (`s.c` 1, `s.v`), moved every tick with the same rule. It can't be shot while carried.
- **Placing:** FIRE or USE. The server runs the same rule on the command's feet and aim and puts it down there facing your way; the streak is used and announced then. A bad spot is refused with a notice and the turret stays in hand.
- **Putting it away:** STREAK again, a weapon switch, a grenade, the knife, selecting another streak or death: a fresh turret goes away and the streak stays ready.
- **Moving it:** USE within 1.7 m of your own placed turret picks it up ("PRESS F TO MOVE SENTRY"; not while it is hacked, nor in its last 2 s). Its lifetime pauses in hand. FIRE / USE puts it down at the new spot; STREAK, a weapon switch, a grenade or the knife put it back where it was; dying puts it down at the preview if that spot is good, else back where it was (BO1 destroyed it then).
- **Counters:** bullets (0.8x); players' frags, semtex and launcher rounds (the weapons feature's new `weapons.detonated` event, with a clear line, 2x); streak blasts (2x); a knife swing at it within 1.9 m in front (destroyed); a flashbang or concussion going off within its radius with a line of sight (stunned 5 s). Hacker Pro: hold USE 2 s beside it; it is out 2.5 s, then shoots for the hacker; nobody can pick up a hacked one.
- **SAM Turret:** the same carry, place, pick-up and put-away flow and the same 1 s arming (BO1 uses one carry path for both); its fire is unchanged (a missile every 2.5 s, 8 missiles, 60 s).
- **Bots** never carry: `callKillstreak(room, bot, 'sentry_gun' | 'sam_turret')` (the automatic use, and a bot's STREAK press) places it at once with `autoTurretSpot`: in front of the bot, facing where enemies are likely to come from (the nearest enemies it knows of, else the enemy team's spawns, else the map's hotspots), trying directions round that until `turretPlacement` accepts one; at its feet if none fits. The `killstreaks.call` RPC does the same.

## Care Package marker (BO1 supply drop canister)

What Black Ops did (`maps/mp/gametypes/_supplydrop.gsc` in the T5 script dump; Call of Duty Wiki "Care Package"): the streak is a grenade-type weapon (`supplydrop_mp`). Calling it puts the canister in your hand; you throw it with the fire button; once it stops moving (`waitTillNotMoving`) the Chinook is sent to it (`heliDeliverCrate(weapon.origin, ...)`), and after the canister's fuse the smoke pours out (`fx_smoke_supply_drop_blue_mp`: **blue** in BO1, the wiki notes MW2's was red). A canister that never settles is deleted after 10 s (`GRENADE_LIFETIME`); a weapon change before the throw stops it.

Ours (`shared/defs/care-marker.ts` for the shared maths, server `streaks/package.ts` and `index.ts`, client `marker.ts`):
- **Raise.** STREAK (4 / D-pad up) with the Care Package selected sets `ks.marker` (pushed as `killstreaks.state.marker`): the gun goes down (the server holds `swapEnd`, so FIRE never shoots), no sprint, and the client shows the canister in a gloved hand (`buildMarkerCanister` in `models.ts`: an olive M18-style can with a blue band, spoon and pull ring), predicted on the press and confirmed by the state push.
- **Preview.** While it is up the client runs the server's own maths every frame from its predicted eye and quantised aim: `markerLaunch` (the grenade release point and velocity, half the thrower's velocity carried), `simulateMarker` (`stepBody` at TICK_DT, the server's tick) and `resolveDrop`. It draws the arc as dots and a landing ring (`ks_drop_ring`, friendly blue) with a "DROP ZONE" waypoint, both over the world like the other waypoints. Where the crate can't come down on the canister the ring turns red with "NO DROP" and the reason, and a yellow ring plus "CRATE HERE" shows where it comes instead. Prompt: "[LMB] THROW MARKER  [4] PUT AWAY" (`promptKey`, so "[RT] ... [↑]" on a pad).
- **Throw.** FIRE (left mouse / RT) throws it (`throwMarker`): the streak is used (`callKillstreak(..., { launch })`), a `ks_marker` entity flies with `markerStep` each tick (bounce `restitution 0.3`, gravity 18), settles, lies on its side and smokes from `s.sm` (1 s after it settles), seen by both teams. The drop goes where it settled (`resolveDrop`, the `killstreaks.marker` room event says where and why): the Chinook flies there and drops the crate (the old heli/crate code, unchanged). The smoke stops 6 s after the crate lands (40 s at most).
- **Where the crate can land** (`resolveDrop`): on the canister when it lies inside the map (1 m in from the bounds, the old designator's clamp), under open sky (no surface more than 0.75 m above it, or the crate would land on the roof), not inside a wall, and no higher than the highest spawn + 4.5 m (roofs nobody can reach). Otherwise: clamp into the map, then walk from there back toward the thrower to the first spot a crate fits, at the canister's own level first (out from under a roof), then any height under the limit (down off a roof); the thrower's spot if nothing nearer works. A canister lost off the map or still moving after 8 s counts as `lost` and uses the same fallback.
- **Put away** (the streak stays ready): STREAK again, a weapon switch, a grenade or the knife, death, or selecting another streak.
- **Bots** never hold a canister: `callKillstreak(room, bot, 'care_package', { target })` (and the automatic use, with `suggestTarget`) works as before; a smoking canister appears at the target and the helicopter leaves at once.
- Remote players see the canister and the smoke, not the canister in the thrower's hand (no third-person pose); the throw plays the usual `weapons.throw` arm swing.

## Valkyrie Rockets (BO1 TV-guided missile)

Sources: the T5 script dump (plutoniummod/t5-scripts): `maps/mp/_tvguidedmissile.gsc`, `gametypes/_killstreak_weapons.gsc`, `_supplydrop.gsc`, `_hardpoints.gsc`, `_globallogic_player.gsc`, `_killstreakrules.gsc`, `_spawning.gsc`; the engine's guided-missile code in the KisakBlack T5 decompile (`g_missile.cpp`: `GuidedMissileSteering`, `MissileTrajectoryClientControlled`, `UpdateGuidedMissileFuelTime`); the weapon file `weapons/mp/m220_tow_mp` (found only in a rebalance mod, so its numbers are a guide); the Call of Duty Wiki "Valkyrie Rockets" page. What BO1 did:
- The 7-kill streak is `m220_tow_drop_mp`: a supply drop marker; the Chinook's crate holds the launcher streak `m220_tow_mp` (a Care Package can roll it too). The drop isn't announced as a Valkyrie.
- The launcher (`useCarriedKillstreakWeapon`) holds 1 + 1 rockets (reload 3 s); you move at 0.8 speed with it. Firing links your view to the rocket at once (`LinkGuidedMissileCamera`) under `tow_overlay` (a reticle) and the grainy `tow_filter_overlay`. The first shot uses the streak: the "inbound" message to everyone, `kls_tv_used` / `kls_tv_enemy` announcer lines.
- Flight: look input steers it at up to 3 degrees per 50 ms frame (60 deg/s) with the sideways acceleration capped (`maxSteeringAccel` 350 u/s², so it turns slower when fast), banking up to 35 degrees, no gravity. `projectileSpeed` 350 u/s; holding the tactical-grenade button (button bit 15) boosts it to 3x, ramping at 1000 u/s² and burning fuel twice as fast; that button and FIRE must be let go once after the launch. FIRE detonates it. Impact explodes it: 400 at the centre, 100 at 7.5 m. Fuel 15 s (the wiki; the mod's file says 20).
- Out of the play area or above 4000 units: "LOSING SIGNAL", the feed fades to white over 2 s and it detonates; back in, the picture fades in over 1 s. When it explodes: 1 s of white "no signal", then you are back in your body.
- Any hit over 5 damage destroys it ("Off The Air", 100 points); SAM Turrets lock on to it (`Target_Set`). It one-shots aircraft. Rockets don't collide with each other.
- Dying doesn't detonate it (only a team change does): it flies on dead straight, and your respawn waits until it is gone plus 2 s (`killstreak_waitamount`). Disconnecting or the game ending detonates it. Putting the launcher away before the first shot keeps the streak; after it, a weapon switch (or death) loses the spare.
- The killcam has no entity for it (`getKillcamEntity` returns undefined for `m220_tow_mp`), so it replays the killer's view: the rocket cam.

Ours (`shared/defs/valkyrie.ts` for the tuning and the flight maths, server `streaks/valkyrie.ts`, client `valkyrie.ts` + `rocketcam-logic.ts`):
- **Drop.** `valkyrie` is `targeting: 'marker'`: STREAK raises the canister, FIRE throws it, the Chinook drops a crate with fixed contents `valkyrie` (no Hardline Pro reroll), announced as a Care Package. Crate contents `valkyrie` (this one, or a Care Package that rolled it) put `VALKYRIE_LAUNCHER` (`valkyrie_launcher`) in the ready list; the HUD calls it "Valkyrie Launcher".
- **Launcher.** STREAK with the launcher selected sets `ks.launcher` (`killstreaks.state.launcher {left, ready, fired}`): 2 rockets, ready after 0.6 s, weapon down, no sprint, speed x0.8, and a `ks_launcher` entity so others see the tube on the shoulder. First person: an olive Strela-style tube with a guidance box on the right shoulder (`buildValkyrieLauncher`), drawn over the world; the HUD shows a launcher sight, "1 /1 VALKYRIE" in place of the ammo, a reload bar, and "[LMB] FIRE ROCKET  [4] PUT AWAY" (`promptKey`). Put away (streak kept before the first shot, spare lost after): STREAK, a weapon switch, a grenade, the knife, selecting another streak, death.
- **Rocket.** FIRE launches a `ks_rocket` from the eye along the aim (`s` = pitch `p`, speed `v`, fuel `f`, boosting `b`, feed white `w`); the first shot removes the launcher from the ready list and sends `killstreaks.called {id: 'valkyrie'}` ("Enemy Valkyrie Rockets inbound"). `ks.control = {id: 'valkyrie', entity, until}` while it flies; the body stands still (speed 0) and can be killed. Each tick `stepRocket` turns it toward the owner's view at `min(1.05 rad/s, 8.9 m/s² / speed)`, flies it at 8.9 m/s, or ramps to 26.7 m/s while the boost bit is held (once it was let go after the launch); fuel 15 s, burning 2x while boosting. It explodes (`ctx.blast`, 7.5 m, 400 to 100, `weapon: 'valkyrie'`, `means: 'killstreak'`, credited to the owner alive or dead) on the world, any player but its owner, an aircraft (destroyed outright), FIRE, empty fuel, or 2 s out of bounds (map bounds + 6 m, or 100 m above the ground; `s.w` ramps the white). Then `control.hold {until, x, y, z}` for 1 s, then you are back with the launcher, which reloads 3 s (`launcher.ready`) before the second rocket; after the second the launcher goes.
- **Hardware.** The rocket is a damageable air entity with 5 hp: one bullet or a SAM missile brings it down and it detonates; the shooter gets 100.
- **Owner death / leave.** Death: the launcher is gone, the rocket flies on unguided, the respawn is held until it explodes, then +2 s ("YOUR ROCKET IS STILL FLYING" on the death screen). Leaving: it detonates.
- **Rocket cam** (client): the camera rides a prediction of our rocket (`predictRocket`: the last snapshot stepped forward by its age plus half the round trip with our current aim and boost, through the same `stepRocket`), eased (`followRocket`) and banked with the turn rate (`bankRoll`, up to 35 degrees). Our look is clamped within 0.45 rad of the nose (`clampLead`), so input past the turn rate doesn't wind up. The picture gets `renderer.feed` (green-grey monochrome, scanlines, a rolling band, grain) under a `tow_overlay`-style HUD: a dithered circular vignette, a cross reticle with corner brackets, "VALKYRIE ROCKET 1/2", a fuel bar, "[LMB] DETONATE", "[Q] BOOST" (a blinking BOOST while it burns), and "LOSING SIGNAL" out of bounds with the white from `s.w`; the hold is white static with "NO SIGNAL". The gun's crosshair and ammo are cleared under it; zoom and ADS sensitivity are off; no controller aim assist.
- **Controls while steering.** Look (mouse / right stick) steers; FIRE (LMB / RT) detonates; boost = the tactical button (Q / LB, as in BO1) or ADS (RMB / LT). The client sends either as the ADS bit and drops the TACTICAL, LETHAL and MELEE bits (`registerButtonFilter`, `rocketButtons`), so the body doesn't throw or stab; the server reads `BOOST_BUTTON` (ADS).
- **Killcam.** A Valkyrie kill's deathcam rides the rocket: the server keeps each rocket's path (`rocketTrack`: 20 Hz, the last 6 s, ending at the blast) and sends it as `cam.track`; the client flies the camera along it under the feed look (`trackPose`), then holds back from the blast.
- **Bots.** `callKillstreak(room, bot, 'valkyrie')` drops the crate where the bot stands and the bot takes it on landing; `callKillstreak(room, bot, VALKYRIE_LAUNCHER)` (or the automatic use, or the bot's STREAK press) raises the launcher; every tick the feature aims at the nearest enemy (a beat to aim, launched a little high), fires, steers with a per-rocket error that shrinks with skill and fades as it closes in, boosts on long runs when skilled, and fires the second rocket after the reload.

## Tactical map (BO1 radio targeting)

What Black Ops did (Call of Duty Wiki pages for Napalm Strike, Rolling Thunder, Mortar Team, Attack Helicopter; gameplay footage, e.g. "Black Ops | Power of the Rolling Thunder" on YouTube): the player calls these in "via a radio" (a handset comes up in the right hand), and an overhead map of the level is laid over the view: a translucent panel with the map name in a black header, a lettered/numbered grid (A1..E5, labels in each cell's top-left), friendly arrows, a prompt bar at the bottom ("Press A to call in Rolling Thunder" / "B Back"). Napalm and Rolling Thunder: position the target and adjust the angle of entry (PC: hold the left mouse button and turn the mouse), shown as orange chevrons along the run; Napalm releases about 4 s after the call, Rolling Thunder about 7 s. Mortar Team: three locations selected one after another, then a delay, two rounds on each, explosions about seven metres across. Attack Helicopter: you designate an area and it hovers near it. MW2's laptop (Precision Airstrike, rotatable arrow) is the secondary reference.

Ours:
- **Open.** STREAK with a map streak selected: the server opens map mode (`ks.map`, pushed as `killstreaks.state.map {id, until}`), spawns a `ks_radio` entity on the caller and holds them still (`speedMultiplier` 0, no sprint, weapon down). The client raises a handset in first person (`radio.ts`, drawn over the world), cuts to the feed with ~0.3 s of static, and shows the map. Other players see the soldier with the rifle slung low and a handset at the ear (`ks_radio` renderer poses the remote soldier). The attack helicopter's radio does not open with a full airspace.
- **Picture.** `overhead.ts` renders the real map straight down with our renderer (orthographic camera over `map.bounds`, same baked lighting and developed textures, sky/fog/wobble off) at the panel's pixel size, then a satellite treatment (a little desaturated, green-grey tint, contrast, scanlines, vignette). Cached per map + time preset + size, re-taken as photos finish developing. The panel sits over a 3-in-4 screen-door of the world (BO1's translucency in our pixel look) with the map name, streak name and a timer in the header, grid with per-cell labels, compass N, rolling feed noise, prompts and the cursor's grid reference in the footer.
- **Shown.** You (yellow arrow with facing), team mates (blue arrows), enemies only when your radar lists them (`snap.radar`: Spy Plane / Blackbird / unsuppressed fire; nothing when jammed), friendly streaks already up (helicopters with their patrol ring, mortar marks, napalm fire, planes, sentry `S`, SAM `A`, crates, dogs, RC-XD).
- **Cursor.** Pointer-lock mouse deltas (1 screen pixel = 1 displayed map pixel), WASD/arrows, gamepad left stick / d-pad; clamped to the bounds. In `?devlook=1` (no real pointer lock) the cursor follows the absolute mouse position, so a real click or drag on the map works.
- **Placement** (`tacmap-logic.ts`, pure): Napalm / Rolling Thunder: press at the target, drag to swing the run (arrow + chevrons + the burn/bomb circles to scale), release to call in; Q/E or the right stick rotate, Enter/Space/A tap confirms at the cursor; the default direction is your facing. Mortar Team: three numbered marks with their 3.5 m blast circles, right click / Backspace / X removes the last, the third confirms. Attack Helicopter: one click picks the patrol point (14 m ring). Esc, STREAK or gamepad B cancels and keeps the streak; dying, the 30 s timeout, changing selection or losing pointer lock also put it away.
- **Server.** RPC `killstreaks.mapTarget {id, points: [x, z][], yaw?}` (`mapmode.ts`): token-bucket rate limit (4 burst, 2/s), the streak must be ready and its map open, then `validateMapTarget` (right count, finite numbers, inside the bounds with 0.5 m slack then clamped 1 m in, finite yaw for line strikes wrapped to (-PI, PI]); the strike logic is unchanged (`callKillstreak` with the chosen targets and yaw). `killstreaks.mapCancel {}` puts the radio away. `killstreaks.call` answers `use_map` for map streaks (no crosshair fallback); the bot API's `callKillstreak` also has no crosshair fallback for them (the helicopter defaults to the map centre).
- **Bots** never open the map: `suggestTarget` aims at clusters of enemies they know about (on their radar or in sight), guessing with twice the error when they know nobody, and passes a run direction along the cluster.
- **Dev:** `window.__lofi.tacmap` (devlook builds): `state()`, `moveTo(x, z)`, `rotate(d)`, `press()`, `release()`, `undo()`, `cancel()`, `screenOf(x, z)` (client pixels of a world point for real clicks). Grant streaks with `killstreaks.cheat` (server with `LOFI_CHEATS=1`).

**Everything targets bots like players.** All AI target selection iterates `room.players` (bots included); all damage goes through `room.damage` / `room.radiusDamage` with `means: 'killstreak'` (napalm ground fire `fire`) and `weapon` = streak id, credited to the owner. Every `fire` event (bots' `room.fire` too) is ray-tested against enemy hardware, so bots can shoot down helicopters and destroy sentries; destroying hardware gives score and emits `killstreaks.destroyed`.

## API for the bots area (`src/server/features/killstreaks/api.ts`)

```ts
import { callKillstreak, readyKillstreaks, suggestTarget, enemyStreakTargets, isDrivingStreak, isDesignating, killstreakState } from '../killstreaks/api';
readyKillstreaks(bot)                              // ['uav', 'napalm']
callKillstreak(room, bot, 'napalm', { target, yaw })   // { ok: true } | { ok: false, reason: 'not_ready'|'dead'|'busy'|'no_target'|'airspace_full'|'phase'|'unknown' }
suggestTarget(room, bot, 'mortar', skill)          // { target, targets, yaw } aimed at clusters of known enemies, error shrinks with skill
knownEnemies(room, bot)                            // enemies on its radar or in line of sight (90 m)
enemyStreakTargets(room, bot)                      // [{ entity, kind, streak, x, y, z, air, hp }] to shoot at
isDrivingStreak(bot)                               // RC-XD / gunner / rockets running (the AI drives them for bots)
isCarryingTurret(p)                                // a Sentry Gun / SAM Turret in hand (humans only; bots' go straight down)
```

- **Automatic use (default):** bots call their own streaks. `player.ext.killstreaks.botStreakUse` (0..1) or `player.ext.bots.skill.streakUse` sets how soon (1.5 s at 1.0, up to ~15 s at 0) and how well (target error, holding a SAM for enemy air and a Counter-Spy Plane for enemy radar, not driving an RC-XD with an enemy in its face). Without either, the lobby default preset (`regular`, 0.6) applies. Set `ext.killstreaks.manual = true` to take over and call `callKillstreak` yourself.
- **Driven streaks for bots** are flown by the feature: RC-XD drives at the nearest enemy and blows up close (skill: steering error, detonate distance), the Valkyrie launcher is fired and its rockets steered at enemies (skill: steering error, boost), the Chopper Gunner aims at visible enemies with skill-scaled error. `isHoldingLauncher(p)` is true while a player holds the Valkyrie launcher.
- **Second Chance for bots:** while `player.ext.perks.lastStand` is set, return `weaponSlot: 1` from the brain (the server switches to the pistol and holds it for 1.5 s with `slotLock`; a brain that keeps sending 0 after that flips it back). A revive puts back the slot the bot went down with.
- **Care Package:** pass a `target` (no canister to hold); `isDesignating(p)` is also true while a player holds the marker canister.
- **Hearing:** read `room.modifiers.any('silentFootsteps', target)` (Ninja) and `room.modifiers.mul('hearingMultiplier', bot)` when bots react to footsteps.

## Integration notes for other areas

- **weapons:** owns the keys it reads (declared in `src/server/features/weapons/state.ts`), and perks registers them under exactly those names: `attachmentSlotsOffset(p, loadout)` (Warlord +1; the spawn trim reads the class being spawned, since `p.loadout` is still the last life's at `beforeSpawn`), `equipmentCountOffset(p, kind)` (Warlord Pro +1), `tacticalMultiplier` (Tactical Mask), `meleeSpeedMultiplier` (Steady Aim Pro), `holdBreathMultiplier` (Scout). Explosive grenades use `means: 'explosive'` (Flak Jacket) and fire `means: 'fire'`.
- **progression:** fold `PERK_PRO_CHALLENGES` into `CHALLENGES`. Their metrics (`perks.*`) are counted by the perks feature straight into `profile.challengeProgress[id]` (don't count them again); award XP when they cross `goal`. - **frontend:** create-a-class uses `perksOfTier(t)` and `KILLSTREAKS` (3 picks; `sanitizeLoadout` already limits). Show Pro via RPC `perks.pro`. - **modes:** streaks reset at `matchStart`; everything ends at the `ended`/`lobby` phase. Wager modes that should have no streaks can give loadouts with `killstreaks: []` in `beforeSpawn`.
- **economy:** `PerkDef.price` / `KillstreakDef.price` are hints; nothing here spends CoD Points.
- **Dev testing:** start the server with `LOFI_CHEATS=1` to enable RPC `killstreaks.cheat { id?, bots? }` (grant a ready streak, add enemy bots), e.g. from the console: `await __lofi.net.rpc('killstreaks.cheat', { id: 'attack_helicopter', bots: 4 })`. Never set it in production.
